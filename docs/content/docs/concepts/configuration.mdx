Relay uses functional options for wiring dependencies and a `Config` struct for tuning runtime behavior.

## Functional options

The `Relay` struct is configured with functional options passed to `relay.New()`:

```go
r, err := relay.New(
    relay.WithStore(postgresStore),
    relay.WithLogger(log.NewProductionLogger()), // github.com/xraph/go-utils/log
    relay.WithConcurrency(20),
    relay.WithPollInterval(2 * time.Second),
    relay.WithBatchSize(100),
    relay.WithRequestTimeout(15 * time.Second),
    relay.WithMaxRetries(8),
    relay.WithRetrySchedule(customSchedule),
    relay.WithCacheTTL(time.Minute),
)
```

### Available options

| Option | Purpose | Default |
|--------|---------|---------|
| `WithStore(s)` | Set the persistence backend (required) | none |
| `WithLogger(l)` | Set the logger, a `github.com/xraph/go-utils/log` `Logger` (not a `*slog.Logger`) | a no-op logger, so you see nothing until you set one |
| `WithConcurrency(n)` | Number of delivery worker goroutines | `10` |
| `WithPollInterval(d)` | How often the engine checks for pending deliveries | `1s` |
| `WithMaxPollInterval(d)` | Cap on the idle backoff, which doubles from the poll interval while polls come back empty | `30s` |
| `WithBatchSize(n)` | Max deliveries dequeued per poll cycle | `50` |
| `WithRequestTimeout(d)` | HTTP timeout per delivery attempt | `30s` |
| `WithHTTPClient(c)` | The client deliveries go out on, for example one whose dialer refuses private addresses. Relay copies it and wraps its transport in the same redacting tracing as its own client, so pass one that isn't traced already | a plain client with the request timeout |
| `WithMaxRetries(n)` | Maximum delivery attempts before DLQ | `5` |
| `WithRetrySchedule(s)` | Backoff intervals between retries | `[5s, 30s, 2m, 15m, 2h]` |
| `WithShutdownTimeout(d)` | Stored in `Config`, but nothing reads it yet. `Stop` cancels the engine and waits for its workers however long that takes | `30s` |
| `WithCacheTTL(d)` | TTL for the catalog's in-memory cache (0 = no cache) | `30s` |
| `WithMetrics(m)` | Delivery metrics, see [Observability](/docs/subsystems/observability). Spans need no option. `WithTracer(t)` is deprecated and does nothing | none |

## Config struct

```go
type Config struct {
    Concurrency     int
    PollInterval    time.Duration
    MaxPollInterval time.Duration
    BatchSize       int
    RequestTimeout  time.Duration
    HTTPClient      *http.Client
    MaxRetries      int
    RetrySchedule   []time.Duration
    ShutdownTimeout time.Duration // not read yet
    CacheTTL        time.Duration
}
```

`relay.DefaultConfig()` returns the defaults in the table above. These fields carry no YAML tags, so when the [Forge extension](/docs/guides/forge-extension) embeds this struct in its own config, you can't set them from a config file. Set them in code.

## Default retry schedule

```go
var DefaultRetrySchedule = []time.Duration{
    5 * time.Second,
    30 * time.Second,
    2 * time.Minute,
    15 * time.Minute,
    2 * time.Hour,
}
```

After all retries are exhausted, the delivery moves to the DLQ.

## Required options

The only required option is `WithStore()`. Without a store, `relay.New()` returns `ErrNoStore`.
